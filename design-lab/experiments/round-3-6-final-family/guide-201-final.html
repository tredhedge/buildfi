Chapter 1

Withdrawal order

Core framework first
The reader should understand why account order matters before they see a withdrawal simulator. This is the clearest difference between a guide and a planning tool.

Teach the sequence before the scenario.

Shared explanation

Different accounts create different tax timing. If the guide only says "take RRSP later" or "preserve TFSA flexibility," it still has not taught the reader the sequence logic behind the advice.

Shared takeaway

Withdrawal order is not a list of best practices. It is a framework for reducing tax drag while protecting flexibility.

Mode contract

  • Interactive mode may compare two withdrawal paths.
  • PDF mode needs a worked sequence example with interpretation.
  • Both outputs keep the same chapter thesis.

Interactive enhancement

Use a comparison strip for two or three withdrawal orders after the framework is explained.

Chapter 2

Tax and OAS protection

Thresholds need plain language
The guide should not assume the reader wants raw tax mechanics. It should translate thresholds and clawbacks into planning consequences.

Explain the planning consequence, not just the threshold.

Advanced readers still benefit from framing. The chapter should say what higher taxable income changes in practice: less OAS retained, less flexibility later, or more pressure on one spouse's income path.

Interactive enhancement

Let the reader compare "base case" versus "high RRSP draw" and see the effect on OAS retention.

PDF/static fallback

Use a threshold callout and a static comparison panel instead of a live slider.

Chapter 3

CPP/QPP and pension timing

Tradeoff before recommendation
This chapter should feel more like a strategic memo than a benefits FAQ. The reader needs to understand what is gained and what is given up by waiting or starting earlier.

Use scenarios to reinforce the chapter, not replace it.

The guide can point to timing scenarios, but only after it explains longevity insurance, portfolio pressure, and the value of predictable income later in retirement.

Chapter 4

Fees and portfolio drag

Small numbers, large consequence
This chapter is a good example of shared architecture: the interactive mode can quantify drag dynamically, while the PDF mode still needs a persuasive static example.

Interactive enhancement

Compare 2.1% fees versus 0.9% fees on the same simplified retirement path.

PDF/static fallback

Show a single long-horizon comparison and explain the flexibility lost to fees over time.

Bonus 301

Advanced levers belong later

Keep complexity ordered
The guide system should protect the reader from complexity too early. Bonus 301 content can exist, but it should clearly feel like an extension rather than part of the core path.

What 201/301 should lock before implementation

Architecture decisions

  • Core 201 and bonus 301 stay distinct in the chapter model.
  • Every advanced interactive block needs a static worked example.
  • The guide shell aligns with the report family without becoming a client deliverable.
  • Tool handoffs happen after the strategy lesson, not instead of it.

Why this matters

This is the round that prevents Guide 201 from becoming half article, half mini simulator. If the mode contract is explicit now, the later refactor can be cleaner and more durable.
