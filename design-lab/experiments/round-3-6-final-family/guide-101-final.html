Part 101 - Foundations

Beginner guides should teach first, then let readers explore.

This pass treats Guide 101 as one guide with two outputs. The beginner should get the same lesson order either way; only the depth of exploration changes.

Start reading See the system contract

System rule: every chapter must stand on its own in PDF, and every interactive block must declare what its static replacement is. That prevents the web guide from becoming the "real" guide and the PDF from becoming a dead export.

Chapter 1

Your financial portrait

Shared in both modes
The lesson stays identical: before budgeting or investing, the reader needs a simple view of assets, debts, income, and monthly pressure points.

Start with the facts, not with goals.

Shared explanation

Many beginners jump straight to "How much should I save?" before they know whether their cash flow is stable, whether debt costs are swallowing progress, or whether they even have a reliable net-worth picture. The guide should always slow that sequence down.

Shared takeaway

A simple asset-versus-liability snapshot is not busywork. It changes what kind of decision should come next.

Mode contract

  • Interactive mode can use a quick net-worth helper.
  • PDF mode needs a worked example and interpretation.
  • Both modes end on the same lesson.

Interactive enhancement

The reader can test a simple asset/liability input pattern after the lesson is explained.

PDF/static fallback

Replace the helper with a representative household snapshot and a one-paragraph interpretation.

Example household: Assets of $23,000 against debts of $18,500 creates a very different next step than someone with the same income but no debt pressure.
Chapter 2

Budgeting for control

Same lesson, different support
This chapter teaches order and pressure, not perfect categorization. The reader needs to see where control comes from before they see a calculator.

Budgeting should lower anxiety, not create more of it.

A guide-first experience explains that a budget is mainly about protecting room for essentials, debt service, and savings. The interactive version can then let the user test different monthly allocations without making the chapter depend on the tool.

Interactive enhancement

Use three or four adjustable categories only after the reader understands what the categories are doing.

Housing 35%
Debt 14%
Savings 8%

PDF/static fallback

Show one balanced monthly example and one stressed monthly example, then interpret the difference in plain language.

Static lesson card If essentials and debt already absorb almost everything, "saving more" is not the right first instruction. The guide needs to say that directly.
Chapter 3

Debt before ambition

Bridge to Product
This is where the guide starts pointing toward the debt tool. The guide teaches why debt cost matters; the tool later helps decide what to do next.

Explain the trap before offering a strategy.

Guide 101 should not become a mini debt tool. It should teach the reader why high-interest balances distort every other plan, then hand off to the more tactical Product surface if they want personalized sequencing.

Interactive enhancement

Offer a simple "minimums vs accelerated payoff" comparison card, not the full production repayment system.

PDF/static fallback

Show one side-by-side debt-payoff example and end with a direct CTA to the debt tool for readers who want a live plan.

Chapter 4

Savings order

Shared chapter close
Guide 101 ends better when it gives the reader a sequence: stabilize cash flow, control expensive debt, then place the next dollar intentionally.

What 101 should lock before implementation

Architecture decisions

  • One chapter data model for web and PDF.
  • Each interactive block must have a defined static replacement.
  • Guide shell stays stable across both outputs.
  • Hand off to the debt tool happens after the lesson, not before it.

Why this matters

If you lock this now, the later guide refactor is much cleaner: content modules, section contracts, and output-specific renderers become obvious instead of improvised.
