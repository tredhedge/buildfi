# Round 2.5 — Implementation Spec

Date: 2026-04-28  
Scope: debt tool, decumulation tool, Guide 101, Guide 201  
Out of scope for this pass: planner, website, AI report production renderer

## Goal

Move from portfolio exploration into a small real implementation slice without touching production-critical surfaces that still need broader direction work.

## Locked Decisions

### 1. Portfolio model

- `Product`: interactive tools, utility-first, cooler slate/navy surface, shared dark/light behavior
- `Reading`: guides and reports, warmer editorial surface, calmer page rhythm
- `Planner Bridge`: deferred; will mediate between Product and Reading later

### 2. Shared tokens

- One shared token module: `lib/design/portfolio-tokens.js`
- Product surfaces consume the same product palette in light/dark mode
- Reading surfaces consume one editorial palette

### 3. Typography

- Product sans: `DM Sans`
- Reading sans: `Inter`
- Reading serif/display: `Playfair Display`
- Numbers/mono: `JetBrains Mono`

Notes:
- This pass sets the stacks at the page/component level only.
- Global font loading and website-wide typography cleanup are deferred until the website/planner pass.

### 4. What this pass should prove

- Debt + decum can feel like one family from one token source
- Guide 101 + Guide 201 can feel like one reading family from one token source
- We can unify without forcing every surface into one visual skin

## Implementation Rules

- No website changes in this pass
- No planner changes in this pass
- No report renderer changes in this pass
- Keep behavior unchanged; focus on shared tokens and visible surface consistency

## Success Criteria

- Both tools import the same Product palette + font tokens
- Both guides import the same Reading palette + font tokens
- Guides get a visible step toward report-style typography
- The pass is small enough to evaluate visually before scaling
