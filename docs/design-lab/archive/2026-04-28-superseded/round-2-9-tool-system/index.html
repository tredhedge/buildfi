Product Family

One Product system, two operating tempos.

Round 2.7 proved debt and decum could live in one family. Round 2.9 goes deeper and makes the system explicit: both tools share the same shell grammar, but decum is slower and more interpretive while debt is tighter and more urgent.

Shared shell

Theme persistence, topbar, summary band, rail, control cards, compare strip, chart wrapper, and action stack should be common patterns.

Decum personality

Calmer pacing, more explanation, longer horizon framing, and more explicit interpretation around trajectories and drawdown choices.

Debt personality

Tighter rhythm, stronger urgency, more operational cues, and clearer payoff strategy contrast without turning into noisy dashboard UI.

What 2.9 is trying to settle

1. Shared Product contract

Both tools should be recognizably BuildFi Product before the user even reads the specific subject matter.

2. Tool-specific density

Decum should feel spacious enough to support thought. Debt should feel sharper and faster without becoming cramped.

3. Navigation and compare logic

Both tools need the same basic interaction grammar: compare baseline to an explored option, keep the baseline clear, and translate charts into actions.
